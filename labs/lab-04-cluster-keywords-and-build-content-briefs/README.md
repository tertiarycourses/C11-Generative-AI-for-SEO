# Lab 4: Cluster Keywords and Build Content Briefs

**Mapping:** LO2 · A1 · K2 · K8  
**Objective:** Map validated keywords to intent-led pages and editorial briefs  
**Deliverable:** Topic-cluster architecture and three approved content briefs  
**Primary source:** https://developers.google.com/search/docs/fundamentals/seo-starter-guide

## Scenario

Useful information architecture groups content by audience tasks and makes important pages reachable through descriptive internal links.

EcoDesk can publish only one pillar page and two supporting articles this quarter, so duplication and weak business fit are expensive.

## Training assumptions and guardrails

- The approved cluster is sustainable office setup for Singapore SMEs.
- EcoDesk has access to an operations specialist for first-party examples.
- Environmental claims require documentary support and cautious wording.
- Existing pages may be consolidated when they serve the same intent.

## Questions

1. Which terms share the same dominant intent?
2. Which page should be pillar, support or conversion content?
3. Where could two proposed pages cannibalise each other?
4. What unique evidence makes each brief publishable?

## Detailed step-by-step procedure

### Step 1: Prepare input

Use only validated rows from Lab 3 and add current-page mapping where relevant.

**Checkpoint:** Save the evidence, file or decision produced before continuing.

### Step 2: Cluster with AI

Ask for group, parent topic, intent, confidence and ambiguous cases; prohibit invented metrics.

**Checkpoint:** Save the evidence, file or decision produced before continuing.

### Step 3: Review ambiguity

Split mixed-intent groups and merge semantic variations that lead to the same page purpose.

**Checkpoint:** Save the evidence, file or decision produced before continuing.

### Step 4: Design architecture

Choose pillar, supporting articles and conversion destination with descriptive internal links.

**Checkpoint:** Save the evidence, file or decision produced before continuing.

### Step 5: Check cannibalisation

Compare title, intent, promise and target query across every proposed page.

**Checkpoint:** Save the evidence, file or decision produced before continuing.

### Step 6: Create briefs

For three pages define audience, answer, angle, evidence, outline, media, links and conversion.

**Checkpoint:** Save the evidence, file or decision produced before continuing.

### Step 7: Add QA gates

Include fact, originality, brand, environmental-claim and SEO checks.

**Checkpoint:** Save the evidence, file or decision produced before continuing.

### Step 8: Publish plan page

Represent the cluster as static HTML cards with clear navigation and no fake performance claims.

**Checkpoint:** Save the evidence, file or decision produced before continuing.
